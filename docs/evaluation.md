# 评测方法与结果

> 所有数字都是本仓库闭环 rollout 的实测值，没有一个占位。评测在仿真里做，
> 没有真机实验。环境是一台无 GPU 的 CPU 机器；评测时机器上还有别的进程在占
> CPU，wall-clock 和吞吐会抖，日志里原样保留了这些波动。

## 1. 评测协议

| 项 | 设置 |
| --- | --- |
| 仿真器 | `so101_sim.GraspEnv`（运动学 + 简化抓取物理，非物理引擎） |
| 控制频率 | 7.5 Hz（60 步 = 8.0 s 一个抓取循环） |
| 观测 | front 96×96×3 + wrist 96×96×3，训练 / 推理统一 resize 64×64 |
| 动作 | 6 维绝对关节目标；ACT chunk=20 |
| 执行策略 | **每 3 步重规划 + 时序集成（temporal ensembling，decay=0.01）** |
| 成功定义 | 指令指定的积木被抓起、转移并**落入盒子内部**（几何判定） |
| 评测 seeds | seen：3000–3019；unseen：4100–4119；lang：3200–3219（与训练 seed 不相交） |
| 语言场景基线 | 同一批 lang seed 上再跑一次无语言输入的 ACT 作为对照 |

**模型和超参的选择没有碰最终评测 seed**：

1. 训练期 checkpoint 选择：验证 rollout 用 seed 5000–5007（训练时每 2 个 epoch
   评估一次），训练日志里能直接查到；
2. 推理超参（replan、时序集成）在 seed 5000–5009 的 10 个验证 episode 上选：

   | 配置 | 验证成功数 /10 |
   | --- | ---: |
   | replan=3, 无集成 | 4 |
   | replan=3, 集成 decay=0.01 | **7** |
   | replan=5, 无集成 | 5 |
   | replan=5, 集成 | 5 |
   | replan=10, 无集成 | 2 |
   | replan=10, 集成 | 4 |

   最后选 `replan=3 + ensemble_decay=0.01`，最终评测在 3000+ / 4100+ 的独立
   seed 上跑。

> 时序集成是 ACT 部署里的常规技巧：每次预测的 chunk 覆盖未来 20 步，对同一个
> 绝对步的多次预测按 `exp(-decay·age)` 加权平均后再执行。只多占一点内存缓存，
> 不增加推理次数。

### seen / unseen 的差异（真实分布漂移）

| 维度 | seen（训练同分布） | unseen（分布外） |
| --- | --- | --- |
| 颜色 | red / blue / green | yellow / purple（**训练中从未出现**） |
| 积木半边长 | 0.017–0.023 m | 0.023–0.027 m（更大） |
| 到基座距离 | 0.150–0.232 m | 0.238–0.258 m（更远） |
| 角度范围 | ±0.55 rad | ±0.85 rad（更偏） |
| 盒子位置 | 0.196–0.232 m | 0.238–0.252 m |
| 滑移概率 | 0.0002–0.0012 / 步 | 0（排除滑移干扰，只测视觉 / 控制泛化） |
| 遮挡物 | 35% 概率出现高遮挡块 | 不出现 |

### 语言条件评测

20 个双积木场景，指令是中文 `把{颜色}积木放进盒子里`（比如「把红色积木放进
盒子里」）。成功 = **指令指定的那个积木**落入盒中。同时统计：

- **指令遵循成功率**（完整任务）= 上述成功率；
- **放错积木率**：错误积木入盒的比例；
- **抓取 grounding**：发生了抓取的 trial 里，抓的确实是指令指定积木的比例。
  这个指标把「语言理解」和「运动精度」拆开，用来判断策略是不是真在看指令。

### 指标定义

- **成功率**：成功 trials / 总 trials。
- **单次循环时间（仿真）**：从 reset 到 episode 结束的仿真秒数（步数 × 0.1333 s）。
- **单次循环时间（wall-clock）**：同一次 rollout 的真实耗时，含每步 96×96 双相机
  渲染、策略推理和动作执行，不含进程启动。
- **单 chunk 推理延迟**：`policy.act(obs)` 的 wall-clock 时间（CPU，batch=1，
  含图像 resize / 归一化，不含仿真渲染）；报告 mean / p50 / p95。
- **失败模式**：`grasp_miss`（抓空）、`slip`（滑移掉落）、`misplace`（放偏，
  含释放点距盒子中心距离）、`timeout`（超时未完成）。

## 2. 复现命令

```bash
# ACT：已见 + 未见各 20 次
python scripts/eval_policy.py --policy act --checkpoint checkpoints/act.pt \
    --replan 3 --ensemble-decay 0.01 --seen-trials 20 --unseen-trials 20 --tag act

# 语言条件策略：20 个双积木场景
python scripts/eval_policy.py --policy lang --checkpoint checkpoints/lang_cond.pt \
    --replan 3 --ensemble-decay 0.01 --lang-trials 20 --tag lang
```

输出 `reports/eval_<tag>.json` 和同名 `.md`，md 里带失败案例描述和失败画面拼图
`reports/eval_<tag>_failures.png`。

## 3. 结果

### 3.1 ACT（单积木抓取-放置）

checkpoint：`checkpoints/act.pt`，0.68 M 参数，2.76 MB；训练过程见 §3.3。

| split | trials | 成功 | 成功率 | chunk 延迟 mean / p95 | 仿真循环 | wall 循环 | 失败模式 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| seen | 20 | 10 | **50.0%** | 15.3 / 38.8 ms | 7.41 s | 0.96 s | slip:1, grasp_miss:9 |
| unseen | 20 | 2 | **10.0%** | 12.4 / 24.5 ms | 7.93 s | 0.83 s | grasp_miss:18 |

按颜色：seen 里 red / blue / green 都有成功（明细在 `reports/eval_act.json` 的
`by_color`）；unseen 里 yellow 0/5、purple 2/15。

### 3.2 语言条件策略（双积木 + 中文指令）

checkpoint：`checkpoints/lang_cond.pt`，0.41 M 参数，1.66 MB。

| trials | 指令遵循成功率（完整任务） | 放错积木率 | 抓取 grounding | 延迟 mean / p95 | 仿真循环 | wall 循环 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 20 | **15.0%** (3/20) | 10.0% (2/20) | **4/4 = 100%** | 20.9 / 51.4 ms | 7.87 s | 1.27 s |

**对照基线**：同一批 20 个语言 scene seed 上，没有语言输入的 ACT 完整任务
成功 5/20 = 25%，抓取 grounding 5/5。也就是说，语言条件策略在这个实验里**没有**
跑赢「闭眼抓一个积木」的同架构 ACT 基线。

**这组数字该怎么读**：

1. 语言策略只有 18 min / 10 epoch 的预算，ACT 是 ~65 min / 多阶段训练；val L1
   分别是 0.140 和 0.133，语言策略的视觉-动作部分明显欠拟合；
2. 抓取 grounding 4/4 说明「指令确实在影响选哪个物体」，但发生抓取的 trial 只有
   4 个，统计上不足以证明语言条件带来了闭环收益；
3. 所以本仓库只声称验证了语言条件链路（中文指令 → 不同动作预测 → 闭环执行），
   不声称语言条件提升了显著成功率。

### 3.3 ACT 训练过程（真实记录）

| 阶段 | 内容 | 耗时 | 结果 |
| --- | --- | ---: | --- |
| 第一段 | 从零训练，长余弦计划（warmup=1350 step） | ~21 min（6 epoch 后停止） | 学习率还在爬升，val L1 0.247，闭环成功率 0 |
| 第二段 | 从第一段 checkpoint 续训，短余弦、LR 4e-4→0.02× | 23.6 min（9 epoch） | val L1 0.142，验证 rollout 成功率 25% |
| 第三段 | 再次续训，短余弦、LR 2.5e-4→0.01× | 20.3 min（10 epoch） | val L1 0.133，验证 rollout 成功率 50%（epoch 8 保存为最终 checkpoint） |
| smoke（CI） | 3 条 episode、2 epoch、batch 16 | 0.26 min | CI 专用，不参与汇报指标 |

> 为什么分三段：训练吞吐远低于预期（跑训练时机器上还有别的任务，
> 单 epoch 从计划的 ~50 s 变成 90–310 s）。长余弦计划在预算内收不了敛，于是改成
> 「续训 + 短余弦」，每段重新退火。全部日志和曲线在 `reports/train_act.json`
> （及同名 `.png`）里，真实 epoch 时间与学习率都保留着。ACT 总训练时长约 65 min。
>
> 关键提升来自 **时序集成**（验证集 4/10 → 7/10）和更多训练（val L1 从 0.153
> 到 0.133）；`replan=1` 反而最差（0/8），说明 chunk 内的动作分布要整体执行。

## 4. 结果解读与局限

1. **仿真不是真机**：抓取成功由几何判定（夹爪位置 + 盒子包含关系），没有真实
   接触力 / 摩擦。成功率说明「模仿学习 + 视觉闭环在这套仿真里能否复现专家」，
   不等于真机成功率。
2. **50% / 10% 是真实结果**：seen 的失败以抓空为主（9/10），诊断显示末端 xy
   误差仍大于 1.2 cm 的抓取容差；unseen 只有 10%，说明当前模型没有泛化到
   「未见颜色 + 更大更远物体」的分布。详见 `docs/failure_cases.md`。
3. **推理超参是验证集选的**，但 10 个验证 episode 方差较大，最终 20 trials 的
   置信区间约 ±10%，别把 50% 和 40% 的差别当显著。
4. **8 s 循环时间是仿真时间**：60 步 × 0.1333 s；wall-clock 约 0.8–1.3 s/次
   （含渲染和推理），这是 CPU 上的仿真速度，不代表真机节拍。
5. **延迟数字只适合同机对比**：ACT 和语言条件策略在同一进程、同一 CPU、
   batch=1 下测，可以横向比较；不代表 GPU 上的延迟。
