# 真机方案：SO-101 遥操作采集与 sim2real

> 本仓库**没有**真机硬件，也没有真机遥操作数据。所有演示数据都由仿真中的
> 脚本专家生成（见 `README.md` 与 `docs/architecture.md`）。本文档是如果
> 要把它落到真实 SO-101 上的实施计划，而不是已完成的记录。

## 2. 遥操作采集流程（80–100 条）

**目标**：80 条成功抓取-放置演示，覆盖初始位姿随机化、颜色/尺寸变化。

1. **机械臂标定**：舵机中位、关节限位、夹爪开合范围；写入
   `calibration/so101.yaml`。检查 IK 是否与真机关节符号一致（本仿真使用
   `[base_yaw, shoulder, elbow, wrist, roll]`，真机上需要核对每关节正方向）。
2. **相机标定**：固定前视相机（尽量与桌面成 45°–60°，保证盒子与积木都可见）；
   腕部相机固定在夹爪上方 2–4 cm，光轴朝下。记录每个相机相对基座的位姿
   （手眼标定可选，ACT 处理像素级视觉，但相机安装误差要记录并保持一致）。
3. **遥操作打通**：主臂拖动从臂，关节位置由主臂舵机读取后写给从臂；
   确认 30 Hz 控制循环、动作不抖动、夹爪开合干净。
4. **采集协议**：
   - 每条演示：随机化初始位姿 → 抓取随机颜色的积木 → 抬升 → 移到盒子上方 → 释放 → 回位；
   - 80 条中红/蓝/绿各约 1/3，初始位姿、盒子位置、相机轻微抖动；
   - 采集时记录 `observation.state`（6 维）、`action`（6 维目标）、
     两路相机（建议 480×640 或 240×320，训练时 resize 到 96×96/64×64）；
   - 成功/失败标记：失败演示**不要**混入训练集，单独存 `failures/` 做复盘；
   - 每条演示耗时约 8–15 s，80 条约 15–20 分钟纯采集时间，加复位约 40 分钟。
5. **数据质检**：
   - 关节/动作范围是否在限位内、是否有跳变；
   - 相机是否被遮挡、时间戳是否对齐（同一控制步采集三路数据）；
   - 播放视频抽查（本仓库 reader 可直接读 LeRobot 风格目录）。
6. **重放验证**：把采集动作在从臂上空跑一遍，确认无碰撞、与视觉一致。

## 3. 标定与相机安装误差（本项目已仿真建模）

仿真里对以下误差做了随机化（`so101_sim/scene.py`）：

| 误差 | 仿真取值 | 真机建议 |
| --- | --- | --- |
| 前视相机位置 | N(0, 1.2 cm) 每 episode | 固定后不再动；改变则必须重新采集 |
| 前视相机朝向 | N(0, 0.8 cm) 目标点抖动 | 标定一次记录外参 |
| 前视相机 FOV | N(0, 1.5°) | 记录实际 FOV，训练时保持一致 |
| 腕部相机偏移 | N(0, 0.6 cm) | 检查是否碰到夹爪行程 |
| 初始位姿 | N(0, 0.10 rad) | 每条演示前随机化并记录 |

真机落地时，**相机安装误差是 sim2real 最大的非视觉差异来源**：仿真中只
随机化了外参，真机还有卷帘快门、运动模糊、曝光差异。建议：

- 训练数据里加入真实采集的相机抖动（换 2–3 个安装角度各采 20 条）；
- 评测时用固定相机，但训练时可用随机裁剪 / 亮度抖动做增广；
- 记录每次安装的相机外参，评测报告里注明。

## 4. sim2real 注意事项

1. **动力学差异**：仿真只有运动学 + 简化抓取规则，真机有重力、摩擦、舵机
   延迟。ACT 输出绝对关节目标，真机上建议先做**低增益位置控制**（柔顺），
   并把速度限制在演示速度的 60–80%。
2. **相机差异**：仿真图像是程序化渲染。真机数据必须**从真机采集训练数据**
   （仿真预训练只能用于验证管线，不能直接部署到真机视觉）。
3. **动作时序**：仿真 7.5 Hz；真机建议 30 Hz 采集与执行，或把动作降采样到
   7.5–15 Hz。chunk 长度 20 在 7.5 Hz 下是 2.7 s，真机上更长，需重新调
   `replan_interval`。
4. **夹爪标定**：仿真的夹爪是 [0,1] 归一化开合；真机是舵机角度，需要线性
   映射并做死区补偿（本仓库的 `gripper` 维度可直接替换）。
5. **安全**：限位、速度限制、急停、工作空间围栏必须放在策略输出之后、驱动器
   之前；不要让学习策略直接控制舵机电流。
6. **成功判定**：仿真用几何判定；真机建议用固定相机 + 颜色/位置检测，
   或人工标注，保证评测标准一致。
7. **评测规模**：真机 20 次 seen + 20 次 unseen 成本较高（约 1–2 小时），
   仿真可先做超参筛选，真机只做最终验收。

## 5. 代码改动清单（真机）

| 模块 | 仿真 | 真机需要替换 / 增加 |
| --- | --- | --- |
| `so101_sim` | 运动学仿真 | 删除 / 不用于真机；改为真实驱动节点 |
| `so101_dataset` | 通用 reader/writer | 可直接用；把 `fps` 改为 30、`image_size` 改为实际分辨率 |
| `so101_policy` | 通用 | 可直接用；按实际相机数量 / 分辨率调整 `ACTConfig` |
| `ros2_ws/.../policy_node.py` | 未运行骨架 | 对接真实话题与驱动，按 `docs/real_robot.md` 与节点内注释修改 |
| 采集脚本 | `scripts/generate_dataset.py` | 换成遥操作采集脚本（可基于 LeRobot 官方 teleoperation） |

## 6. 验收标准（真机）

- [ ] 80 条成功演示 + 失败案例集（≥10 条）
- [ ] 相机外参、关节标定文件入库
- [ ] 20 seen + 20 unseen 真机评测，记录成功率 / 单次循环时间 / 失败模式
- [ ] 与仿真结果的差距分析（sim2real gap）
- [ ] 安全测试：限位、急停、越界不动作
- [ ] README 同时给出仿真与真机两套数字，明确区分
