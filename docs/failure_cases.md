# 失败案例集（真实记录）

> 这里记的坑都是开发过程中真踩过的，评测里的失败案例也是真观测到的。
> 仿真环境，无真机。

## A. 开发过程中踩的坑（已修复，复盘留着）

### A1. 夹爪滑移概率公式写反：专家成功率从 80% 掉到 40% 的「假故障」

**现象**：仿真环境搭好后，脚本专家在 40 个随机种子上只成功 32 个，失败全部标成
`slip`（刚要抬起就掉）。日志里滑移甚至发生在夹爪完全闭合之后。

**怎么查的**：

1. 先怀疑随机滑移概率（`slip_prob ∈ [0.0005, 0.004]`），31 步搬运的理论滑移率
   应该只有 ~7%，但实测失败率 20%，对不上；
2. 逐帧打印 `_update_grasp`，发现每次都在「夹爪完全闭合」附近掉；
3. 翻代码：额外滑移项写成了 `slip += 0.02 * max(0, 0.25 - opening)` ——
   `opening=0`（完全闭合）时这一项最大，`opening=0.2` 时反而小，逻辑反了。

**修复**：改成 `slip += 0.05 * max(0, opening)`（只在夹爪没完全闭合时增加滑移
风险），基础滑移概率降到 `[0.0002, 0.0012]`。修完 40 个种子 40/40 成功，正式
数据生成 79/80 成功，1 条因滑移丢弃重采。

**教训**：仿真里的「随机失败」要能用概率解释；解释不了，基本就是确定性 bug。

### A2. 统计量共用一个 count，算出 `mean < min`

**现象**：`pytest tests/test_dataset.py::test_stats_are_consistent` 失败，
`meta/stats.json` 里某些维度的 `mean` 小于 `min`。

**原因**：`StatsAccumulator` 用了一个全局 `self.count`，但 state 和 action 是
两次 `update` 累积的。`count = 2×60`，而每个特征的 `sum` 只累计自己的 60 帧，
均值被除以 120，变成真值的一半。

**修复**：每个特征独立 `counts[key]`；测试保留「min ≤ mean ≤ max」断言。
**教训**：统计量这种「看起来显然对」的代码最容易埋 bug，一定要有性质测试。

### A3. CI smoke 训练崩溃：`zero-size array to reduction operation`

**现象**：`--smoke` 只用 3 条 episode，但默认 `val_episodes=8`，训练集被切成
0 帧，`np.min` 对空数组报错。

**修复**：缓存 / 切分逻辑里对 `val_episodes` 做 clamp（至少留 1 条训练、1 条
验证），smoke 模式走独立 cache 路径，避免污染正式缓存。
**教训**：训练脚本要在「只有 1 条数据」的极端规模下也能跑通，否则 CI 不可信。

### A4. 渲染太慢，数据生成耗时超标 4 倍

**现象**：第一版渲染器每个观测 33 ms（双相机），而且 `rollout_expert` 每步渲染
两次（记录一次 + `env.step` 返回一次），80 条数据要 ~9 分钟。

**修复**：

1. 静态背景（桌面网格、阴影）在 `reset` 时缓存，wrist 视角不画网格；
2. 立方体面做背面剔除，盒子的 4 面墙只画可见面；
3. rollout 复用 `env.step` 返回的观测，每步只渲染一次。

**结果**：观测降到 ~12 ms（双相机），80 条 episode 生成 137 s（ACT）/ 165 s
（lang）。

### A5. IK 解的选择：负 elbow 解超关节限位

**现象**：解析 IK 先取 `q3 = -acos(...)` 时，大部分桌面目标算出的 `q2` 超过
±2.8 rad 限位。

**修复**：同时枚举 `q3 = ±acos(...)` 两组解，按 `|q2|+|q3|+0.25|q4|` 成本选
可行解（实际总是「正 elbow」构型更自然）。测试里对 5 个典型目标做 IK→FK 往返
（误差 < 1e-6 m），并断言工具方向严格朝下。
**教训**：2R 平面臂的两组解都要检查，否则总有一片工作空间会「IK 失败」。

### A6. 动作归一化统计的泄漏风险

**现象**：最初想用全量 `meta/stats.json` 的均值和方差做动作归一化，这样验证
episode 的统计信息就进了训练。

**修复**：训练缓存的归一化统计只用训练 split 的 episode 计算，写进 checkpoint；
评测时用 checkpoint 里的统计反归一化，训练 / 推理对齐，验证集也干净。测试用
min ≤ mean ≤ max 和逐维 std > 0 覆盖。
**教训**：归一化统计也是训练数据的一部分，不能泄漏验证集。

### A7. 语言条件策略不能靠哈希词袋

**现象**：最初打算用字符 n-gram 哈希做语言特征。哈希是固定的，模型没法通过训练
学会「红色」和「蓝色」对应哪个物体，只能死记颜色位置；换到 unseen 颜色更是没有
意义。

**修复**：改成**字符级可训练 token embedding**（词表从指令语料构建，含中文
单字），mean-pool + MLP 投影到 transformer token 空间；checkpoint 里存词表，
评测时未知字符映射到 `<unk>`。测试覆盖中文编码、padding、`<unk>`，以及
「不同指令必须产生不同动作预测」。

### A8. 训练吞吐低于预期

**现象**：预计每个 epoch ~50 s，实测首个 epoch 134 s，后面受机器上其他任务影响
到 270–300 s。

**影响**：预算内只跑到 10 个左右 epoch。报告里如实记录 `throughput steps/s` 和
`epoch_seconds`，没有夸大训练规模。
**下一步**：把图像降到 48×48、减小 chunk，或者换一台空闲的机器，吞吐能翻倍。

## B. 评测中观测到的失败案例

完整的失败清单和失败画面拼图在 `reports/eval_*.md` 里，下表是人工摘录。

### B1. ACT 评测（最终 checkpoint `act.pt`，replan=3 + 时序集成 decay=0.01）

20 个 seen trial 成功 10 个（50%），20 个 unseen trial 成功 2 个（10%）。
seen 失败模式：`grasp_miss` 9、`slip` 1；unseen 失败模式：`grasp_miss` 18。

| seed | split | 失败模式 | 现象 | 可能原因 |
| ---: | --- | --- | --- | --- |
| 3000 | seen | slip | 抓取后运输中积木滑落（随机滑移概率） | 仿真域随机化的滑移概率命中 |
| 3001 | seen | grasp_miss | 场景带遮挡块，抓空 | 遮挡下视觉定位误差变大 |
| 3002 | seen | grasp_miss | 场景带遮挡块，抓空 | 同 3001 |
| 3004 | seen | grasp_miss | 场景带遮挡块，抓空 | 同 3001 |
| 4101+ | unseen | grasp_miss | 黄色 / 紫色积木多数抓空 | 颜色从未在训练出现；尺寸更大、位置更远，误差被放大 |

**失败分析**

1. **末端精度不够是主因**：失败时夹爪 xy 误差约 2.0 cm（抓取容差 ~1.2 cm）。
   策略学会了接近-下降的整体轨迹，但没有收敛到 cm 级定位。最终模型 val L1 =
   0.133（归一化动作空间），训练 L1 = 0.097，已经接近这个容量和分辨率下的
   收敛平台。
2. **遮挡场景更差**：摘录的 seen `grasp_miss` 里好几个带遮挡块；front 相机被
   遮住时腕部相机视野有限，策略缺少定位信息。
3. **没有失败恢复**：策略是 chunk 执行 + 重规划，抓空之后不会自动重试。
4. **unseen 只有 10%**：颜色变化本身对纯关节预测影响有限，但 unseen 的积木更大
   （0.023–0.027 m vs 0.017–0.023 m）、位置更远（0.238–0.258 m vs
   0.150–0.232 m），需要更大的动作幅度和不同的视觉尺度，泛化失败。
5. **推理超参影响显著**：验证 seed 上 replan=1 是 0/8、replan=3 是 4/10、
   replan=10 是 2/10；加上时序集成后 replan=3 升到 7/10。最终评测用
   replan=3 + 时序集成。

### B2. 语言条件策略评测（`lang_cond.pt`，replan=3 + 时序集成）

20 个双积木场景：完整任务成功 3/20（15%），失败模式 `grasp_miss` 16、`slip` 1；
抓取 grounding 4/4（发生抓取的 4 个 trial 全部抓的是指令指定积木），放错积木率
10%。

**对照**：同一批场景、同一推理配置下，无语言输入的 ACT 成功 5/20（25%），
grounding 5/5。语言策略没跑赢盲选基线。

**原因**：

1. 训练预算只有 18 min / 10 epoch（ACT 约 65 min / 多阶段），语言策略的视觉-
   动作部分欠拟合（val L1 0.140 vs ACT 0.133，训练 L1 0.130 vs 0.097）；
2. 发生抓取的 trial 太少（4 个），grounding 的统计置信度低；
3. 语言条件要求模型同时解决「选哪个物体」和「cm 级操作」。在 0.41 M 参数、
   64×64 输入和这点训练预算下，更容易欠拟合。

> 结论：这个仓库验证了语言条件链路（中文指令 → 不同动作预测 → 闭环执行），
> 但当前预算下没有证据表明它带来了闭环成功率收益。负结果照原样留着，不当卖点。
